# 流复制




## 主库操作

主配置文件 postgresql.conf 不需要修改

修改 pg_hba.conf
```conf
# 添加一行，指定备库的地址，如果有多个，也可以设置为一个网段
host    replication     all             x.x.x.x/32          scram-sha-256
```



创建用户
```sh
sudo -u postgres psql -c "CREATE ROLE replicator WITH REPLICATION LOGIN ENCRYPTED PASSWORD '你的密码';"
```



## 备库操作


清空目录
```sh
systemctl stop postgresql
rm -rf /data/postgresql/15/main/*
```

备库执行
```sh
sudo -u postgres pg_basebackup \
  -h <主库IP> \
  -U replicator \
  -D /data/postgresql/15/main \
  -Fp -Xs -P \
  --write-recovery-conf
```

启动
```sh
systemctl start postgresql
```




## 同步复制


流复制默认是异步的，可以通过sql查询，主库执行
```sh
sudo -u postgres psql -c "SELECT client_addr, state, sync_state FROM pg_stat_replication;"
 client_addr |   state   | sync_state 
-------------+-----------+------------
 10.10.203.9 | streaming | async
(1 row)
```

如果要改为同步复制，则修改修改配置文件
```conf
# replica1 为备库的自定义名字
synchronous_standby_names = '1 (replica1, replica2, replica3)'
```

备库操作
```sql
ALTER SYSTEM SET primary_conninfo='.... application_name=replica1';
```

进pgsql执行sql
```sh
sudo -u postgres psql
```

重新设置主库连接字符串，此操作会重新覆盖 postgresql.auto.conf
```sql
ALTER SYSTEM SET primary_conninfo =
'user=replicator password=''xxx'' channel_binding=prefer host=x.x.x.x port=5432 sslmode=prefer sslnegotiation=postgres sslcompression=0 sslcertmode=allow sslsni=1 ssl_min_protocol_version=TLSv1.2 gssencmode=prefer krbsrvname=postgres gssdelegation=0 target_session_attrs=any load_balance_hosts=disable application_name=replica2';

-- 重新加载配置
SELECT pg_reload_conf();
```


主库执行，可以看到 sync_state 变为sync了
```sh
sudo -u postgres psql -c "SELECT client_addr, state, sync_state FROM pg_stat_replication;"
 client_addr |   state   | sync_state 
-------------+-----------+------------
 10.10.203.9 | streaming | sync
(1 row)
```


## 其他


备库的两个重要配置文件
* standby.signal
  * 启动为 备库模式（不会允许写入）
  * 不再创建新 WAL，而是等待从主库同步日志
  * 读取 primary_conninfo（主库连接参数）即 postgresql.auto.conf 的内容
* postgresql.auto.conf
  * 通过 pg_basebackup 自动生成
  * 启动优先级 postgresql.auto.conf > postgresql.conf，相同配置auto文件会覆盖 主配置文件
  * 存储主库连接参数


---
**备库启动流程**
* 启动备库时 PostgreSQL 会按以下顺序工作：
  1. 看到 standby.signal → 确定自己是备库
  2. 读取 postgresql.auto.conf → 获取 primary_conninfo
  3. 通过 primary_conninfo 创建复制连接
  4. 进入 streaming 复制模式
  5. 备库以只读方式对外提供服务
