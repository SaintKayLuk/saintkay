## 外键

外键（FOREIGN KEY） 主要用于保证数据的完整性和一致性，它在一个表的某个字段上创建，并指向另一个表的主键字段。


外键的作用
* **保持数据一致性**：防止插入不合法的数据。例如，订单 表中的 用户ID 必须是 用户 表中已存在的 ID。
* **保证数据完整性**：防止删除或更新数据时破坏表间关系。例如，不能删除 用户 表中仍然被 订单 表引用的用户。
* **维护表的关系**：让 MySQL 自动处理级联操作（CASCADE）。


外键选项，被外键关联的表 update 和 delete 的时候根据选项有不同效果

| 选项     | 作用                                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| CASCADE  | 级联删除/更新，主表的数据删除/更新时，外键表中相关的数据也会被删除/更新             |
| SET NULL | 置空，主表数据删除/更新时，外键表中的外键字段值被设为 NULL（前提是该字段允许 NULL） |
| RESTRICT | 拒绝操作，如果从表中存在关联数据，则拒绝删除/更新（默认行为）                       |



* 外键的作用：保证数据完整性，防止删除/更新导致数据不一致。
* 外键删除/更新选项：
  * CASCADE（级联删除/更新）
  * SET NULL（主表数据删除时，从表字段设为 NULL）
  * RESTRICT / NO ACTION（限制删除/更新，防止破坏数据）
* 实际使用建议：
  * 如果希望删除主表数据时自动删除从表数据 → CASCADE
  * 如果希望删除主表数据时不删除，但清空外键字段 → SET NULL
  * 如果要完全禁止删除主表数据 → RESTRICT（默认）


建表示例
```sql
--- 创建 orders 表，表中 user_id 字段建立外键于 users 表的 user_id 字段
CREATE TABLE orders (
    order_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT,
    order_date DATE,
    FOREIGN KEY (user_id) REFERENCES users(user_id) 
    ON DELETE CASCADE  -- 用户删除时，订单也删除
    ON UPDATE CASCADE  -- 用户ID更新时，订单表中的user_id也跟着更新
);

```
