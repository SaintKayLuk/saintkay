## 备份

备份两部分，一个配置文件 /etc/gitlab，一个数据，包括代码等其他数据


#### 备份配置文件

```sh
sudo gitlab-ctl backup-etc
```
    ↓
    ↓备份默认位于
    ↓
```
/etc/gitlab/config_backup
```

#### 备份数据文件

数据文件还原，需要原始配置文件里的  gitlab.rb 和 gitlab-secrets.json，所以配置文件也需要备份

```sh
#备份数据命令，是 gitlab-rake gitlab:backup:create 的包装
gitlab-backup create
    ↓
    ↓备份默认位于
    ↓
/var/opt/gitlab/backups
```

* 备份排除，linux软件包自编译方式安装的gitlab
  * db（数据库）
  * repositories（Git 存储库数据，包括 wiki）
  * uploads（附件）
  * builds（CI 作业输出日志）
  * artifacts（CI 作业工件）
  * pages（页面内容）
  * lfs（LFS 对象）
  * terraform_state（地形状态）
  * registry（容器注册表镜像）
  * packages（套餐）
  * ci_secure_files（项目级安全文件）
  * external_diffs（外部合并请求差异）

例如跳过 CI 作业工件 和 容器注册表镜像
```sh
sudo gitlab-backup create SKIP=artifacts,registry
```

## 恢复




您安装了与创建备份 完全相同版本和类型 (CE/EE)的 GitLab。
sudo gitlab-ctl reconfigure您至少 已跑过一次。
GitLab 正在运行。如果没有，请使用 启动它sudo gitlab-ctl start。


sudo cp 11493107454_2018_04_25_10.6.4-ce_gitlab_backup.tar /var/opt/gitlab/backups/
sudo chown git:git /var/opt/gitlab/backups/11493107454_2018_04_25_10.6.4-ce_gitlab_backup.tar


sudo gitlab-ctl stop puma
sudo gitlab-ctl stop sidekiq
# Verify
sudo gitlab-ctl status


# This command will overwrite the contents of your GitLab database!
# NOTE: "_gitlab_backup.tar" is omitted from the name
sudo gitlab-backup restore BACKUP=11493107454_2018_04_25_10.6.4-ce



把 gitlab.rb 文件 secrets文件 以及ssl的证书等都放好，然后重启

sudo gitlab-ctl restart
sudo gitlab-rake gitlab:check SANITIZE=true
sudo gitlab-rake gitlab:doctor:secrets


改了gitlab.rb 文件后，需要 gitlab-ctl reconfigure
