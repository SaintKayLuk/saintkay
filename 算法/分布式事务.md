# 两阶段提交协议（2PC）


**准备阶段（Prepare Phase）**
1. 事务协调者（Coordinator）发送准备请求：事务协调者向所有参与者（Participants）发送一个准备请求（Prepare Request），询问它们是否准备好提交事务。
2. 参与者准备：每个参与者在接收到准备请求后，执行必要的操作，确保能够提交事务。如果参与者能够成功执行操作，它们将锁定相关资源，并将自己置于准备状态。
3. 参与者响应：参与者将它们的决策（准备提交或回滚）发送回协调者。如果参与者准备好提交事务，它们会发送准备好（Ready to Commit）响应；如果它们无法提交事务，它们会发送回滚（Abort）响应。

**提交阶段（Commit Phase）**
1. 协调者决策：事务协调者根据所有参与者的响应做出决策。如果所有参与者都准备好提交事务，协调者会发送提交请求（Commit Request）；如果有任何一个参与者无法提交事务，协调者会发送回滚请求（Rollback Request）。
2. 参与者执行：参与者在接收到协调者的提交请求后，提交事务；在接收到回滚请求后，回滚事务。
3. 参与者响应：参与者执行完提交或回滚操作后，发送确认（Acknowledgement）给协调者，确认操作已完成。
4. 事务完成：协调者在收到所有参与者的确认后，事务结束。协调者记录事务的最终状态。



#### 优点：

一致性保证：确保分布式系统中所有参与者在事务提交时保持一致。

#### 缺点：

* 同步阻塞：参与者在准备阶段锁定资源，直到事务完成，可能导致资源长时间锁定。
* 单点故障：协调者的故障可能导致整个系统无法继续进行事务。
* 网络分区问题：在网络分区或参与者超时情况下，协议可能会挂起，导致系统无法做出决策。
