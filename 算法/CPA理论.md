## CAP理论


| 缩写 | 名称                           | 含义                                               |
| ---- | ------------------------------ | -------------------------------------------------- |
| C    | Consistency 一致性             | 所有节点访问同一数据时，都能获得相同的结果         |
| A    | Availability 可用性            | 每个请求都能在有限时间内获得响应（不保证是最新的） |
| P    | Partition tolerance 分区容错性 | 系统在出现网络分区（节点之间通讯断开）时仍能运行   |



CAP 定理的核心结论：
**在一个分布式系统中，最多只能同时满足其中两个，不可能同时兼顾三者。**




💡 各大系统是怎么选择的？

| 系统类型                      | CAP 选择     | 说明                                                                 |
| ----------------------------- | ------------ | -------------------------------------------------------------------- |
| 关系型数据库（如 MySQL 主从） | CA（理论上） | 主从网络断开时，为了防止数据不一致，主机会拒绝写入，牺牲了分区容忍性 |
| NoSQL（如 Cassandra）         | AP           | 保证可用性和分区容忍性，牺牲强一致性                                 |
| Zookeeper、etcd               | CP           | 牺牲可用性，保证强一致和分区容忍（例如网络异常时拒绝服务）           |
| Redis Sentinel 模式           | AP（偏向）   | 尽可能可用，但主从切换可能出现数据不一致                             |



分布式系统中，P（分区容忍性）是必须的，因为网络不可避免会出问题。
**所以真正要选的是：一致性（C） 和 可用性（A） 哪个更重要。**
