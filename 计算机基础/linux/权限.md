
## 普通权限

### 文件目录权限
长格式显示的时候，此10位代表文件或者目录的权限

```sh
#最后一个点，是代表所受selinux增强保护
#最后一个+，代表此文件或目录拥有acl权限
-rwxr--r--.+
```




第一位，代表文件类型

~~~
-   代表普通文件
d   代表目录
l   代表软链接
b   块设备文件，存储设备文件为此格式，u盘，硬盘等
~~~

~~~
r  读权限
w  写权限
x  执行权限
~~~
可以用数字来表示，4表示r, 2表示w, 1表示x

* 第2-4位，所有者权限
* 第5-7位，所属组权限
* 第8-10位，其他人权限

权限命令
~~~shell
chmod [ugoa][+-=][rwx]  xxx

赋予123文件所有者执行权限
chmod u+x 123
赋予123文件所有者读写权限，其他读权限
chmod 644 123
~~~

目录权限，只有0，5，7权限，目录的x权限，代表可以cd进入目录
对于删除文件，必须对上级目录有w的权限，文件名保存在上级目录i节点

修改所有者和所有组
~~~sh
chown [-R]          #修改所有者，所有组(-R修改目录下的子目录和文件)
chgrp [-R]          #修改所有组

chown user xxx      #修改xxx文件的所有者为xxx
chown user:user xxx #修改xxx文件的所有者和所有组为user
chown user.user xxx #所有者和文件组中间用: 或者. 连接
~~~


#### 默认权限

~~~
umask
~~~

umask默认 022 ，对应的默认文件权限644，默认目录权限755

umask值计算 默认权限
* 文件：文件最大默认权限 666 减去 022 得到 644
* 目录：目录最大默认权限 777 减去 022 得到 755

#### 权限对文件和目录的作用

文件最大默认权限666，即新建文件默认不能有执行权限，只能通过 chmod 添加文件的 执行权限
目录最大默认权限777，目录的 x 权限仅仅是能够进入目录



##### 文件

* r 能够读取文件内容
* w 能够修改文件内容
* x 能够执行文件，能否执行成功取决于文件脚本得正确性

##### 目录

* r 对目录有读权限的时候，可以查看目录下有哪些内容，即可以使用 ls 命令查看目录下的有哪些子目录和文件  
* w 对目录有写权限，可以修改目录下的数据，即可以在目录下新建，复制，删除，剪切子目录或文件
* x 对目录有执行权限，因为目录不能执行，所以对目录有执行权限的时候，可以进入目录，即 cd 命令

对于目录来说，权限只有几个值有意义当权限为

* 权限为0(---)：任何权限都不赋予
* 权限为1(--x)：只能进入目录，什么也干不了，没有意义，即只有 cd 命令
* 权限为2(-w-)：因为没有目录的执行权限，所以不能读取目录下的状态，也不能目录下的文件，即新建，删除，复制等等，其实什么也干不了，没有意义
* 权限为3(-wx)：能进入目录，能操作文件，新建，删除等，但是不能查看目录下的文件，没有意义
* 权限为4(r--)：只能查看目录下的一级目录名字和文件名，因为文件名或目录名存在于上级目录中，没有意义
* 权限为5(r-x)：能进入目录，能查看目录下的文件和子目录，但是不能操作目录下文件，即不能创建，删除，复制文件
* 权限为6(rw-)：因为没有执行权限，不能进入cd，即不能读取目录下的文件状态，同4权限相同，只能查看目录下的文件和一级子目录名
* 权限为7(rwx)：最高权限，能进入目录，查看目录下文件，创建，删除，移动文件等

所以目录的有意义的权限只有 0 , 5 , 7

#### 用户信息文件
~~~
vi /etc/passwd

root:x:0:0:root:/root:/bin/bash
bin:x:1:1:bin:/bin:/sbin/nologin
...
~~~

* 第一列：用户名
* 第二列：密码位，有x代表有密码，密码在/etc/shadow文件中查看  
* 第三列：用户ID
  * 0：超级用户UID
  * 1-499：系统用户(伪用户)uid
  * 500-65535：普通用户UID
* 第四列：初始组ID,新建用户时会建立同名组，用户组信息在/etc/group文件中查看
* 第五列：用户说明
* 第六列：用户家目录，超级用户/root，普通用户/home下 
* 第七列：登陆shell， /bin/bash能登陆，/sbin/nologin不能登陆 等...


#### 用户影子文件(密码文件)

~~~
vi /etc/shadow

root:$1$K1WU5zcrME$Hx21nlgRmqkrYx0D3eY7mEgWi1:18492:0:99999:7:::
bin:*:17110:0:99999:7:::
...

~~~
文件权限为 000 ，只有root用户能修改，切强制保存 :wq! 才能生效

* 第一列：di用户名
* 第二列：加密后的密码(sha512)，所有伪用户都是不能登陆的，密码为 * 或 !! 可以在某个用户密码前加一个 ! 临时限制登陆
* 第三列：密码最近更改时间，时间戳，对于1970年1月1日过去的天数
* 第四列：两次密码修改的间隔时间，默认为0，可以修改密码，例:设为5，则5天内不能修改密码，两次密码修改间隔必须大于5天
* 第五列：密码有效期，默认99999，永久生效，基于第三列
* 第六列：密码到期前的警告天数，基于第五列，还剩几天过期则每次登陆会警告
* 第七列：密码到期后的宽限天数，默认-1，在此文件中不显示即-1，永不过期，基于第五列
* 第八列：密码失效时间，如果超过此失效时间，无论密码有没有过期，都不能登陆，到期后，会在第二列密码前加一个 " ! "
* 第九列：保留


#### 组信息文件
~~~
/etc/group
~~~

* 第一列：组名
* 第二列：组密码位，密码位于 /etc/gshadow ，不建议给组添加密码
* 第三列：GID，组ID
* 第四列：组附加用户，只能看到组支持的附加用户

初始组：每个用户初始组有且只能有一个，一般都是和用户名相同的组作为初始组
附加组：每个用户可以属于多个附加组，要把用户加入组，都是加入附加组

## ACL

用于解决用户对文件身份不足



默认开启，如果没有开启
```sh
#重新挂载根分区，并挂载加入 acl 权限，临时
mount -o remount,acl /

#修改/etc/fstab 文件，在defaults后面加acl
defaluts,acl
#重新挂载
mount -o remount /
```

查看是否开启
```
查看根分区的路径，例如是/dev/sda2
[root@localhost ~]# df 


查看是否支持acl
[root@localhost ~]# dumpe2fs  -h /dev/sda2 | grep acl
Default mount options:    user_xattr acl
```

查看acl权限
```sh
getfacl [文件/目录]
```

设置acl权限
```
setfacl [选项] [文件/目录]
    -m      设置acl权限
        u       赋予用户
        g       赋予用户组
        d       默认权限，只能赋予目录，即此目录下的新建文件目录都有默认acl权限
        m       最大权限，mask，所有acl权限和mask权限的与所得最终acl权限
    -x
        u       删除某个用户acl权限
        g       删除某个用户组的acl权限
    -b      删除所有acl权限
    -R      递归赋予权限，只能对目录使用

```

例：赋予u1用户 对abc目录的 rx权限，可以使用rwx的方式，也可以使用数字，比如5权限代表rw
```
setfacl -m u:u1:rx abc/
```
例：赋予用户组g1 对 a.txt 文件的 rw 权限
```
setfacl -m g:g1:rw a.txt
```

例：赋予u1用户对abc目录的rx权限，并递归作用于目录下所有文件目录
并且赋予abc目录的默认acl权限
```sh
#对当前已存在文件目录有效
setfacl -mR u:u1:rx abc/
#对目录下新增文件目录有效
setfacl -m d:u1:rx abc/ 
```

例：删除acl权限
```sh
#删除abc目录的用户u1的acl权限
setfacl -x u:u1 abc/
#删除abc目录的用户组u1的acl权限
setfacl -x g:u1 abc/
#删除abc目录的所有acl权限
setfacl -bR abc/
```

例：设置abc目录的mask权限为r--
```sh
#设置abc的mask
setfacl -m m:r abc/
#再给u1用户赋予abc目录的rx权限，最终只能得到r选线
```

## sudo

让普通用于拥有其他用户拥有的执行权限，一般来说，给普通用户设置root用户才能执行的命令的权限


用户执行一个命令时，会查找 /etc/sudoers 文件，判断是否拥有权限
更改sudo权限使用 visudo 命令，即打开的是 /etc/sudoers 文件
```sh
#相当于打开/etc/sudoers 文件，但是在保存时会检查内部语法，建议使用visudo命令
visudo 
  ||
/etc/sudoers
```

/etc/sudoers 文件格式
```
root    ALL=(ALL)       ALL

此配置表示root用户拥有所有主机所有用户的权限
第一列：表示设置的需要sudo权限的用户，如果是组则加%，例如 %wheel 表示wheel组
第二列ALL：ALL可以写IP或者网段，指可以管理那个ip地址的服务器，建议都写ALL
第二列=(ALL)：指可以切换为什么用户，ALL表示可以切换所有用户，不写表示切换为root用户
第三列ALL：表示可以执行所有命令，一般指定绝对路径的命令加参数，越详细权限越精确



## Same thing without a password 让用户或者组在sudo时候不需要输入密码
# %wheel        ALL=(ALL)       NOPASSWD: ALL
```

例：授权 u1 用户拥有root用户的 shutdown -r now 的权限
```sh
#编辑 /etc/sudoers 文件，用visudo命令打开
visudo

#添加一行，不指定=(ALL)，则表示是root的命令权限
# (ALL)可以省略，但是建议写上
u1  ALL=  /usr/sbin/shutdown -r now
u1  ALL=(ALL)  /usr/sbin/shutdown -r now
#保存退出即生效
```

例：授权 u2 用户可以查看所有docker容器的日志，并且不需要输入密码
```sh
u2  ALL=(ALL)  NOPASSWD: /usr/bin/docker logs *
```

例：授权 u2 用户可以添加用户和修改普通用户密码(除了root用户)
```sh
#编辑 /etc/sudoers 文件，用visudo命令打开
visudo


#默认执行命令的路径，如果命令在其他路径下(例如/usr/local/bin)，可以添加路径或者把命令cp到以下路径
Defaults    secure_path = /sbin:/bin:/usr/sbin:/usr/bin
#添加 useradd 权限
u2 ALL=/usr/sbin/useradd
#添加 passwd 权限，并且排除修改 root 用户，多个参数使用 逗号加空格分隔
u2 ALL=/usr/bin/passwd [a-zA-Z0-9]*, !/usr/bin/passwd "", !/usr/bin/passwd root
```


普通用户使用 sudo 命令
```sh
sudo [命令]
    -l      #查看拥有的 sudo 权限的列表
    命令    #执行拥有的 sudo 权限的命令
```

例：u1用户使用sudo的useradd命令添加zhangsan用户
```sh
sudo useradd zhangsan
```

## chattr和lsattr

限制root用户的操作权限，添加此权限后root用户也不能操作，但是root用户可以取消此权限限制

```
chattr [-RVf] [+-=] [ia] [文件/目录]
    -R      递归
    +/-     添加或者取消权限(+是添加权限，-是取消权限)
    i       对文件而言：不能修改删除新增，即什么操作都不能，只能查看
            对目录而言：不能新增和删除目录下的文件，但是可以修改目录下文件的内容，目录下文件内容由文件的chattr决定
    a       对文件而言：可以追加内容，但是不能修改和删除原有内容，不能使用vi打开编辑，可以通过 echo 追加
            对目录而言：可以在目录下新增文件和目录，但是不能删除和修改文件和目录名
```

attr权限不能通过ls -l 查看有任何不同，只能通过lsattr来查看
```
lsattr [选项] [文件/目录]
    -R      只有针对目录时有作用，会显示目录下所有子文件和子目录
    -d      查看目录
    -a      只有针对目录时有作用，会显示目录下当前级的文件和目录，不会显示子目录下的内容
```
