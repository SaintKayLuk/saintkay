## 系统运行级别

|运行级别|含义|
|-|-|
|0|关机|
|1|单用户模式，主要用于系统修复|
|2|不完全的命令行模式|
|3|完全的命令行模式，就是标准字符界面|
|4|系统保留|
|5|图形模式|
|6|重启动|

~~~
runlevel            查看系统的运行级别
init 运行级别        改变当前的运行级别

例：查看系统当前运行级别
runlevel
N 3

会显示2个数字，前一个数字代表系统前一个运行级别，后一个数字代表当前的运行级别，N表示没有前一个运行级别

例：改变当前运行级别
init 0
相当于关机，但是不建议这么使用，容易造成数据丢失，推荐使用shutdown
~~~

### /etc/rc.d/rc.local

系统启动时执行一次，相当于开机启动文件，需要开机自启得程序可以放这里

```sh
[root@localhost ~]# ll /etc/rc.local 
lrwxrwxrwx. 1 root root 13 9月  11 2019 /etc/rc.local -> rc.d/rc.local
```

/etc/rc.local 是  /etc/rc.d/rc.local 的软连接
rc.local 开机不生效，查看/etc/rc.d/rc.local 是否 有执行权限

```sh
chmod +x /etc/rc.d/rc.local 
```


## 系统启动过程


**centos6.x**



1. 上电，加载BIOS，BIOS自检
2. 加载启动引导程序 GRUB 


第一个启动的进程 init

**centos7.x**


1. 上电，加载 BIOS，BIOS自检
2. 加载启动引导程序 GRUB2，解析配置文件 /boot/grub2/grub.cfg
3. 内核引导，加载 /boot/vmlinuz 和 /boot/initramfs
4. 内核初始化，挂载真正根文件系统
5. 内核启动第一个进程 /usr/lib/systemd/systemd
6. /usr/lib/systemd/systemd 调用默认单元组  -> /lib/systemd/system/default.target，并且并行调用以下单元组
   * /lib/systemd/system/sysinit.target.wants/*  初始化系统
   * /lib/systemd/system/basic.target.wants/*   准备操作系统
   * /lib/systemd/system/multi-user.target.wants/*  字符界面所需程序    
   * /etc/rc.d/rc.local 执行文件中内容
   * /lib/systemd/system/getty.target.wants/* 初始化本地终端


第一个启动的进程 systemd

## centos7 救援修复


* vmlinux是ELF文件，是编译出来的最原始的内核文件；
* vmlinuz是被压缩的linux内核，是可以被引导的（GRUB2）

启动失败或者其他问题，一般都是 /boot 目录下文件损坏或者缺失，或者 /etc/fstab 自动挂载失败

### /boot下的启动所需文件都存在，只是引导出问题

此操作相当于，linux不知道怎么启动，而我们手动去引导启动内核

#### bios方式引导

1. 将 GRUB 的根设备设置为与 GNU/Linux 相同的驱动器
可以先用用 set 先看一下 root=什么
```sh
search --set=root --file /vmlinuz
```
这里的 root 是指 GRUB 的根文件系统 和 内核的根文件系统，而不是系统的
GRUB 的根文件系统和 Linux 内核的根文件系统通常是同一个。
通常情况下，这是包含 /boot 目录的分区，因为这里存储了 GRUB 的引导文件和 Linux 内核
所以如果知道 /boot 分区是什么，第一步也可以直接设置
```sh
set root=/dev/sda1
```

2. root=/根分区，首先要知道根分区是什么，也可以用uuid表示 root=UUID=xxx
如果不知道 根分区是哪个，可以查看根分区下的 /etc/fstab 文件，查看一下根分区的UUID 是多少
```sh
grub> linux /vmlinuz... root=/dev/sda1
或
grub> linux /vmlinuz... root=UUID=xxx
```
如果你的系统只有两个分区，一个用于 /boot，另一个用于 /，
那么 root=/dev/sdXY 应该指向根文件系统所在的分区，而不是 /boot 分区。
假设 /boot 分区是 /dev/sda1，根分区是 /dev/sda2，那么正确的命令应该是：
```sh
linux /vmlinuz... root=/dev/sda2
```
如果有2个分区一个为 /boot 路径为 /dev/sda1 ，另一个 / 分区，路径为 /dev/sda2
因为 /boot 分区只包含引导文件，而不包含根文件系统。因此，引导过程需要将根文件系统挂载到正确的分区，即 /dev/sda2，以确保系统能够正确启动。
当您将 root 参数设置为 /dev/sda2 时，GRUB 引导加载程序将根文件系统挂载到正确的分区，从而允许系统正常引导。
而如果您将 root 参数设置为 /dev/sda1，系统将会尝试将根文件系统挂载到 /boot 分区上，这将导致引导过程失败，因为 /boot 分区并不包含根文件系统。


3. 如果使用 initrd，则执行命令，是否使用initrd 是由内核编译时决定的，默认开启
```sh
grub> initrd /init...img
```

4. 针对32位的 grub使用 linux16 和 initrd16
```sh
grub> linux16 /vmlinuz... root=/dev/sda1
grub> initrd16 /init...img
```

5. 启动boot
```sh
grub> boot
```

6. 重新进入系统后，重新生成 grub.cfg 引导文件
```sh
grub2-mkconfig -o /boot/grub2/grub.cfg
```

#### uefi方式引导

uefi方式一般会有3个分区
```sh
/
/boot
/boot/efi
```

基本操作和 bios引导 的一致

可以用set看一下在哪，也可以重新设置到 efi 的分区下
需要注意的是， vmlinxz 和 initramfs 并不一定在 efi 分区下
```sh
# 例如 efi 分区为 (hd0,gpt1)  ， boot 分区为 (hd0,gpt2) ， 当我们要手动引导时候
linuxefi (hd0,gpt2)/vmlinuz... root=/dev/sda3
initrdefi (hd0,gpt2)/initramfs...
boot
```




### 使用u盘等镜像工具，重新进入系统，基本可修复所有问题

1. 插上u盘，虚拟机测试挂载 cdrom
2. 修改bios启动项为u盘
3. 进入centos的安装界面
   ```
   Install CentOS 7                         #直接安装centos7
   Test this media & install CentOS 7       #测试这个介质，（u盘等，安装这个iso的）和安装centos7

   Troubleshooting                          #故障排除
   ```
4. 选择 Troubleshooting
5. 选择 Rescue a CentOS system
6. 输入 1 （Continue）
7. 直接回车
8. 切换根目录
   ```sh
   chroot /mnt/sysimage
   ```
9.  挂载u盘，光盘等
    ```sh
    mount /dev/sr0 /media
    ```
10. 修复grub，当然这个sda是你系统的盘，看具体安装系统是 sda还是sdb等
    ```sh
    grub2-install /dev/sda
    ```
11. 重新安装内核
    ```sh
    rpm -ivh --force /media/Packages/kernel-3.10....
    ```
12. 生成 grub.cfg 文件
    ```
    grub2-mkconfig -o /boot/grub2/grub.cfg
    ```
13. 同步数据到硬盘，可以多执行几次
    ```sh
    sync
    sync
    ...
    ```
14. 退出重启，拔下u盘，或者重新修改bios启动项
    ```sh
    exit
    reboot
    ```
